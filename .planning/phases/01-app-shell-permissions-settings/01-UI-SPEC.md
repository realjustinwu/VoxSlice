| Property | Value |

## Typography

Uses SF Pro via SwiftUI's system font APIs. All sizes in points (macOS standard).

| Role | Size | Weight | SwiftUI API | Line Height |
|------|------|--------|-------------|-------------|
| Body | 13pt | .regular (400) | `.body` or `Font.system(size: 13)` | 1.38 (default) |
| Label | 11pt | .medium (500) | `.caption` or `Font.system(size: 11, weight: .medium)` | 1.27 (default) |
| Heading | 17pt | .semibold (600) | `.headline` or `Font.system(size: 17, weight: .semibold)` | 1.29 (default) |
| Display | 28pt | .bold (700) | `Font.system(size: 28, weight: .bold)` | 1.21 (default) |

**Implementation note:** Use SwiftUI semantic typography styles (`.title`, `.headline`, `.body`, `.caption`) as primary, with explicit sizes only for custom overrides. This ensures Dynamic Type and accessibility behavior works correctly.

## Color

Follows macOS system colors. Supports both Light and Dark mode automatically.

| Role | Value (Light / Dark) | Usage |
|------|---------------------|-------|
| Dominant (60%) | `.windowBackgroundColor` (#FFFFFF / #1E1E1E) | Main window background, settings pane surface |
| Secondary (30%) | `.controlBackgroundColor` (#F5F5F5 / #2A2A2A) | Settings sidebar, grouped content areas, card backgrounds |
| Accent (10%) | `.controlAccentColor` (#0058D0 / #3B82F6) | Primary CTA buttons, active tab indicator, recording indicator dot, permission status "granted" badge |
| Destructive | `.systemRed` (#FF3B30 / #FF453A) | Error states, permission denied indicators, validation failure text |

Accent reserved for: Record button (inactive state in Phase 1), primary action buttons in Settings ("Validate Key", "Save"), permission status "granted" checkmarks, active sidebar selection

## Component Inventory

Phase 1 requires these UI components:

### Menu Bar
- **Menu bar icon**: SF Symbol `waveform.circle` (idle), `waveform.circle.fill` (recording -- Phase 2). 18x18pt rendered in template mode.
- **Dropdown menu**: Standard `NSMenu` with items:
  - "VoxSlice" header (disabled, bold)
  - Separator
  - "Settings..." (opens Settings window, `cmd + ,`)
  - "About VoxSlice"
  - Separator
  - "Quit VoxSlice" (`cmd + Q`)

### Permissions Screen
- **Permission card** (repeated for Screen Recording and Microphone):
  - Icon: SF Symbol (`display` for Screen Recording, `mic` for Microphone)
  - Title: Permission name
  - Description: Why VoxSlice needs this permission
  - Status badge: "Granted" (green checkmark) / "Not Granted" (yellow warning)
  - Action button: "Open System Settings" (appears when not granted)
- **Screen Recording restart notice**: Inline banner explaining app must restart after granting Screen Recording permission. Uses `NSAlert` style information.

### Settings Window
- **Window dimensions**: 520pt wide x 420pt tall (fixed, not resizable)
- **Title**: "VoxSlice Settings"
- **Tab structure**: SwiftUI `TabView` with labeled tabs:
  - Tab 1: "General" (STT provider selection)
  - Tab 2: "API Keys" (key management)

#### General Tab
- **STT Provider selector**: SwiftUI `Picker` with options:
  - "OpenAI Whisper API"
  - "WhisperKit (Local)" (disabled with label "(Coming Soon)" -- deferred to v2)
  - Placeholder for future providers
- **Output folder**: Path display with "Choose..." button (`NSOpenPanel`)
- **Output folder default**: `~/Documents/VoxSlice`

#### API Keys Tab
- **STT API Key field**: `SecureField` with placeholder "Enter your OpenAI API key"
- **Validate button**: "Validate Key" -- calls OpenAI models endpoint to verify key validity
- **Validation states**:
  - Idle: Button enabled, no status
  - Validating: Button shows spinner, disabled
  - Valid: Green checkmark + "Key verified" text
  - Invalid: Red x + "Invalid API key. Check your key and try again." text
- **AI API Key field**: `SecureField` with placeholder "Enter your AI provider API key" (same OpenAI key for v1)
- **Key storage**: All keys stored in macOS Keychain via `Security` framework, never `UserDefaults`

### About Window
- Standard `NSWindow` with app icon, version, copyright
- Uses macOS standard About panel pattern

## Interaction Patterns

### App Launch Flow
1. App launches, menu bar icon appears
2. No dock icon (LSUIElement = true in Info.plist -- menu bar only app)
3. Check permissions on launch
4. If any permission missing: Show permissions window automatically
5. If all permissions granted: User interacts via menu bar only

### Permission Flow
1. User sees permission cards with current status
2. User clicks "Open System Settings" button
3. App opens specific System Settings pane via URL scheme:
   - Screen Recording: `x-apple.systempreferences:com.apple.preference.security?Privacy_ScreenCapture`
   - Microphone: `x-apple.systempreferences:com.apple.preference.security?Privacy_Microphone`
4. User grants permission in System Settings
5. User returns to VoxSlice -- app polls permission status every time window becomes active
6. For Screen Recording: If newly granted, show alert "VoxSlice needs to restart to use Screen Recording. Restart now?" with "Restart" and "Later" buttons

### Settings Flow
1. User opens Settings via menu bar > Settings or `cmd + ,`
2. User selects STT provider
3. User enters API key in secure field
4. User clicks "Validate Key"
5. Validation runs (async with spinner)
6. On success: Key saved to Keychain, green confirmation
7. On failure: Error shown inline, key NOT saved

## Accessibility

- All interactive elements have accessibility labels via `.accessibilityLabel()`
- Permission status uses `.accessibilityValue()` for screen readers
- Tab navigation follows standard macOS keyboard order
- SecureField uses `NSAccessibility.Role.secureTextField`
- Color is never the sole indicator -- always paired with icon or text label
- Dynamic Type: Use semantic font styles so users can override sizes in System Settings
