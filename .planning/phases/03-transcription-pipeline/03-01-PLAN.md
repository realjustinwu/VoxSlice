Key implementation details for TranscriptionService:

**whisperX HTTP API communication (D-01/D-05):**
- POST to `{whisperXURL}/transcribe` with multipart form data containing the audio file
- The request should include parameters: `language` (auto-detect), `diarize` (true for speaker diarization per D-04)
- Use URLSession with a 600-second timeout (long recordings take time)
- Parse the JSON response which contains: `segments` array with `start`, `end`, `text`, `speaker` fields; `language` string; `word_segments` (optional)

**whisperX response parsing (D-07/D-08):**
- Map whisperX `segments[].speaker` (e.g., "SPEAKER_00") to Speaker struct
- Map whisperX `segments[].start/end` to Segment.startTime/endTime
- Extract unique speakers from segments to build Speaker array
- Set language from response, duration from recording info, provider = "whisperX"
- Generate transcript filename from recording timestamp per D-09

**Dual-stream merging (D-13):**
- Use AVAudioEngine offline rendering or AVAsset to merge mic.m4a and system.m4a into a single file
- Mix both audio sources at equal volume into a single M4A file
- Save merged file temporarily in the recordings directory, delete after transcription
- If merge fails, fall back to sending system audio only (contains meeting content)

**Health check:**
- GET `{whisperXURL}/health` -- expect 200 response
- Return specific error messages per UI-SPEC: "Could not connect to whisperX at [URL]" for unreachable, "whisperX returned an unexpected response" for non-200

A utility struct (not a service -- stateless) that handles audio file splitting for long recordings:

```swift
import Foundation
import AVFoundation

struct AudioChunker {
    /// Check if a file needs to be chunked based on size per D-11
    /// Returns true if file exceeds AppConstants.maxUploadFileSize (24MB)
    static func shouldChunk(fileURL: URL) -> Bool { ... }

    /// Calculate how many chunks are needed based on file size
    static func calculateChunkCount(fileURL: URL) -> Int { ... }

    /// Split an audio file into chunks of AppConstants.defaultChunkDuration (10 minutes) each
    /// Returns array of temporary file URLs for each chunk
    /// Uses AVAsset export with time ranges
    static func splitAudioFile(_ fileURL: URL, chunkDuration: TimeInterval = AppConstants.defaultChunkDuration) async throws -> [URL] { ... }

    /// Merge transcript segments from multiple chunks into a single TranscriptInfo
    /// Adjusts timestamps: chunk 2 segments have chunk 1 duration added to start/end
    /// Reconciles speaker IDs across chunks (SPEAKER_00 in chunk 1 and chunk 2 map to same speaker if voice matches,
    /// but since whisperX processes independently, keep them as-is with note that speaker mapping is per-chunk)
    static func mergeChunkResults(
        chunks: [TranscriptInfo],
        recordingId: UUID,
        totalDuration: Double,
        language: String,
        audioFilePath: String
    ) -> TranscriptInfo { ... }

    /// Clean up temporary chunk files
    static func cleanupChunks(_ chunkURLs: [URL]) { ... }
}
```

Key implementation details:

**splitAudioFile:**
- Use AVAsset(url:) to load the merged audio file
- Use AVAssetExportSession to export time ranges: CMTimeRange(start: offset, duration: chunkDuration)
- Export as M4A (same format as source)
- Save chunks to a temporary directory inside the recordings folder
- Handle edge case: last chunk may be shorter than chunkDuration

**mergeChunkResults:**
- Concatenate segments from all chunks
- Offset timestamps: for chunk index i, add (i * chunkDuration) to each segment's startTime and endTime
- For speakers: since each chunk is processed independently by whisperX, the same physical speaker may get different IDs across chunks. Use a simple strategy: prefix speaker IDs with chunk index (e.g., "SPEAKER_00" in chunk 0 becomes "SPEAKER_00", in chunk 1 becomes "SPEAKER_00" -- keep as-is since whisperX/pyannote doesn't correlate across chunks). Deduplicate speakers by ID after merging.
- Sum durations, take language from first chunk (or majority vote if they differ)

**2. Update `VoxSlice/Services/TranscriptionService.swift`:**

Add chunked transcription logic to the `transcribe(recording:)` method:

In the transcribe method, after merging dual-stream audio:
1. Check `AudioChunker.shouldChunk(fileURL: mergedAudioURL)`
2. If no chunking needed: send directly to whisperX, parse response, save
3. If chunking needed:
   a. Update step to `.chunkProgress(current: 0, total: chunkCount)`
   b. Split audio file using AudioChunker.splitAudioFile
   c. For each chunk: send to whisperX, parse into TranscriptInfo, update progress
   d. Merge all chunk results using AudioChunker.mergeChunkResults
   e. Clean up temporary chunk files
   f. Save merged transcript

The progress calculation for chunked transcription:
- Preparing: 0% - 10%
- Each chunk: 10% - 90% (distributed evenly across chunks)
- Processing speakers: 90% - 95%
- Saving: 95% - 100%

For non-chunked (single file):
- Preparing: 0% - 20%
- Sending: 20% - 80%
- Processing speakers: 80% - 95%
- Saving: 95% - 100%

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| App -> whisperX HTTP service | Transcription requests sent over local HTTP (user's machine). Audio data leaves the app process but stays on localhost. |
| whisperX response parsing | Untrusted JSON from external service parsed into app models. Malformed responses could crash or corrupt data. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering | TranscriptionService.sendToWhisperX | accept | whisperX runs on user's localhost -- user controls the endpoint. Tampering risk is equivalent to running untrusted local software which user has already chosen to do |
| T-03-02 | Denial of Service | TranscriptionService.transcribe | mitigate | Implement 600-second timeout on whisperX HTTP requests. Cancel in-flight requests if user triggers retry. Clean up temp files on failure |
| T-03-03 | Information Disclosure | AudioChunker.splitAudioFile | accept | All audio files and temp chunks stored in user's Application Support directory with standard macOS file permissions. No network transmission of chunks |
| T-03-04 | Spoofing | TranscriptionService healthCheck | accept | No authentication between app and local whisperX service. URL is user-configured, runs on localhost by default |
| T-03-05 | Tampering | parseWhisperXResponse | mitigate | Validate all JSON fields before creating TranscriptInfo. Use guard/binding for required fields. Default/empty values for optional fields. Never force-unwrap |
| T-03-06 | Information Disclosure | TranscriptionService whisperX URL | accept | URL stored in UserDefaults (not Keychain) per D-02 -- it is a local HTTP address, not a secret |
</threat_model>
