## Interaction Patterns

### Post-Recording Auto-Transcription Flow

Per D-10: RecordingCoordinator triggers transcription automatically after recording stops.

```
1. Recording stops (user clicks Stop or silence detected)
2. Menu bar icon changes to doc.text.below.ecg (transcribing state)
3. Dropdown menu shows "Transcribing..." with progress bar
4. Progress updates:
   a. "Preparing audio..." — merging/processing audio files
   b. "Sending to whisperX..." — uploading audio chunks
   c. "Transcribing chunk 1 of 3..." — per-chunk progress (if long recording)
   d. "Processing speakers..." — speaker diarization
   e. "Saving transcript..." — writing JSON to transcripts/ directory
5a. On success:
   - Menu bar shows checkmark.circle briefly (2 seconds)
   - Dropdown shows "Transcription complete" with summary (speakers, language)
   - Icon reverts to idle waveform.circle
5b. On failure:
   - Menu bar shows exclamationmark.triangle (orange)
   - Dropdown shows error message with "Retry Transcription" button
   - Icon stays in failed state until user dismisses or retries
```

### whisperX Settings Configuration Flow

```
1. User opens Settings > Transcription tab
2. User enters whisperX service URL (default: http://localhost:8000)
3. User clicks "Validate Connection"
4. App sends health check request to whisperX service
5a. On success: Green checkmark, "Connected" status, service capabilities displayed
5b. On failure: Red error, specific message (unreachable / invalid response)
6. URL saved to UserDefaults when field changes
```

### Retry Transcription Flow

```
1. User sees "Transcription failed" in menu bar dropdown
2. User clicks "Retry Transcription"
3. System re-attempts from the beginning
4. Same progress flow as auto-transcription
5. If repeated failures: suggest checking whisperX service in Settings
```

## Data Display Patterns

### Transcript JSON Format (Standardized)

Per D-07/D-08: The output JSON schema that the UI and downstream phases consume:

```json
{
  "id": "UUID",
  "recordingId": "UUID",
  "language": "zh",
  "duration": 3600.5,
  "speakers": [
    { "id": "SPEAKER_00", "label": "Speaker 1" },
    { "id": "SPEAKER_01", "label": "Speaker 2" }
  ],
  "segments": [
    {
      "speaker": "SPEAKER_00",
      "startTime": 0.0,
      "endTime": 5.42,
      "text": "Transcribed text content here"
    }
  ],
  "transcribedAt": "2026-04-07T10:30:00Z",
  "provider": "whisperX"
}
```

This schema is not directly rendered in Phase 3 UI but is the data contract for Phase 5 (Dashboard + Playback).

## Accessibility

- Menu bar transcription status uses `.accessibilityValue()` for screen readers (e.g., "Transcribing, 75 percent complete")
- Progress bar has `.accessibilityLabel("Transcription progress")`
- Settings form fields follow standard macOS accessibility with labels and hints
- Color is never sole indicator — always paired with icon (checkmark vs xmark) and text label
- "Retry Transcription" button has `.accessibilityHint("Retry the failed transcription")`
