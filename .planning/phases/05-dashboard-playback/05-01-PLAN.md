**1. Create VoxSlice/Models/RecordingHistoryItem.swift** with:

```swift
import Foundation

// Processing status computed from file existence on disk per D-06
enum ProcessingStatus: Equatable {
    case new           // Recording metadata exists, no transcript
    case transcribing  // Currently being transcribed
    case transcribed   // Transcript exists, no analysis
    case analyzing     // Currently being analyzed
    case completed     // Transcript + analysis both exist
    case failed        // Transcription or analysis failed
}

// Aggregated view model for a single recording in the dashboard
struct RecordingHistoryItem: Identifiable {
    let id: UUID
    let recording: RecordingInfo
    let transcript: TranscriptInfo?
    let analysis: AnalysisResult?
    let status: ProcessingStatus
    var displayTitle: String
    var displaySummary: String?
}
```

The `displayTitle` is computed as: first `analysis.topics.first?.name` if available, else formatted date string using `"MMM d, yyyy 'at' h:mm a"` format.
The `displaySummary` is computed as: `analysis?.summary.tldr` if available, else nil.

**2. Create VoxSlice/Services/RecordingHistoryService.swift** as an `@Observable @MainActor` class:

Dependencies: `StorageService` (injected), `RecordingCoordinator` (optional, for live transcription/analysis state).

Properties:
- `var recordings: [RecordingHistoryItem] = []` -- sorted newest first by `recording.startTime`
- `var isLoading: Bool = false`
- `var searchText: String = ""`
- `var filteredRecordings: [RecordingHistoryItem]` -- computed: if searchText is empty, returns recordings; otherwise filters where any of these match case-insensitively: displayTitle, any transcript segment text, analysis summary tldr, analysis summary detailed, any action item text, any decision text, any topic name. Debounce is handled by the UI layer (300ms in the search field onChange), not in the service.

Methods:
- `func loadRecordings()` -- scans recordings/ directory for `*.json` files using `storageService.directoryURL(for: AppConstants.recordingsDir)`, decodes each as `RecordingInfo`. For each recording, checks for matching transcript in transcripts/ by matching the timestamp prefix (recording filename minus `_mic` suffix and extension, then look for `{prefix}_transcript.json`). For each recording, checks for matching analysis in analysis/ by looking for `{prefix}_analysis.md`. Builds `RecordingHistoryItem` with computed status and display title/summary. Sorts by `recording.startTime` descending. Handles missing/corrupted files gracefully (skip them, log error).

- `func refreshRecordings()` -- calls loadRecordings() to rebuild the list. Should be called on notification observers for transcription/analysis completion.

- `func updateLiveStatus(recordingId: UUID, isTranscribing: Bool, isAnalyzing: Bool, isFailed: Bool)` -- updates the ProcessingStatus of the matching recording in the list for the current session's live transcription/analysis state.

- `func recordingURL(for item: RecordingHistoryItem) -> URL?` -- returns the merged audio file URL for playback. Looks for `{timestamp}_merged.m4a` in recordings/ directory. Returns nil if file does not exist.

ProcessingStatus computation logic:
1. If `updateLiveStatus` was called with `isTranscribing=true` for this recording -> `.transcribing`
2. If `updateLiveStatus` was called with `isAnalyzing=true` for this recording -> `.analyzing`
3. If `updateLiveStatus` was called with `isFailed=true` for this recording -> `.failed`
4. If transcript JSON exists AND analysis MD exists -> `.completed`
5. If transcript JSON exists AND no analysis MD -> `.transcribed`
6. Otherwise -> `.new`

Match logic for finding transcript/analysis by recording: The recording metadata filename pattern is `YYYY-MM-DD_HH-MM-SS_metadata.json` (from RecordingInfo.metadataFilePath). The timestamp prefix is extracted by removing `_metadata.json`. Then:
- Transcript: `{prefix}_transcript.json` in transcripts/
- Analysis: `{prefix}_analysis.md` in analysis/
- Merged audio: `{prefix}_merged.m4a` in recordings/

|----------|-------------|
| Disk -> RecordingHistoryService | JSON/metadata files read from user's configured output directory. Corrupted or tampered files could cause crashes. |
| TranscriptionService -> Filesystem | Merged audio file write to recordings/ directory. Path derived from internal state (trusted). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Tampering | RecordingHistoryService.loadRecordings() | mitigate | Use `try?` when decoding JSON files from disk. Skip corrupted/unreadable files gracefully. Never crash on bad data. |
| T-05-02 | Tampering | RecordingHistoryService.loadRecordings() | mitigate | Validate file paths stay within expected output directory. Use `URL.appendingPathComponent` not string concatenation. |
| T-05-03 | Information disclosure | RecordingHistoryService | accept | Recording metadata files contain file paths and timestamps - no PII. Local-only storage, standard macOS file permissions apply. |
| T-05-04 | Denial of service | RecordingHistoryService.loadRecordings() | accept | Very large number of recordings could cause slow loading. Acceptable for v1 - user would need thousands of recordings to notice. |
