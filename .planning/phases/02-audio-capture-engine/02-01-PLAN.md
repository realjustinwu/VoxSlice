<objective>
Build the core dual-stream audio capture engine that simultaneously records microphone audio (via AVAudioEngine) and system audio (via ScreenCaptureKit) to separate M4A files. Includes health monitoring (silence detection), device change handling, and proper file output with 44.1kHz / 128kbps AAC settings.

Purpose: This is the highest-risk technical component of the entire project. Capturing system audio on macOS requires ScreenCaptureKit with screen recording permission, and coordinating two independent audio streams with different sample rates is the core challenge. Getting this right is essential for all downstream features.

Output: AudioCaptureService (dual-stream capture engine), RecordingInfo model, RecordingState enum.
</objective>

Create `VoxSlice/Services/AudioCaptureService.swift` implementing the full dual-stream audio capture engine. This is a complex service with the following architecture:

```
@Observable
@MainActor
final class AudioCaptureService {
    // Published state
    var state: RecordingState = .idle
    var currentRecording: RecordingInfo?
    var elapsedDuration: TimeInterval = 0
    var audioLevels: (mic: Float, system: Float) = (0, 0)  // 0.0-1.0 for UI metering
    
    // Dependencies
    private let storageService: StorageService
    private let permissionManager: PermissionManager
    
    // Internal capture components
    private var audioEngine: AVAudioEngine?        // Microphone capture
    private var micAudioFile: AVAudioFile?          // Mic file writer
    private var systemAudioFile: AVAudioFile?       // System file writer
    private var screenCaptureStream: SCStream?      // ScreenCaptureKit stream
    private let audioQueue = DispatchQueue(label: "com.voxslice.audio", qos: .userInitiated)
    
    // Silence detection
    private var silenceStartTime: Date?
    private var silenceCheckTimer: Timer?
    
    // Device monitoring
    private var deviceChangeNotifications: [NSObjectProtocol] = []
    
    // Elapsed timer
    private var durationTimer: Timer?
}
```

**Key methods to implement:**

1. `init(storageService:StorageService, permissionManager: PermissionManager)` — Store dependencies, set up device change notification observers using `NotificationCenter.default.publisher(for: AVAudioApplication.deviceChangeNotification)` (or equivalent macOS notification for audio device changes).

2. `startRecording() throws` — Full flow:
   a. Check `permissionManager.allPermissionsGranted` — if false, throw `RecordingError.noPermission`
   b. Generate timestamp-based filenames per D-10: `YYYY-MM-DD_HH-mm-ss_mic.m4a` and `YYYY-MM-DD_HH-mm-ss_system.m4a` in the recordings directory
   c. Create `RecordingInfo` with state `.recording`
   d. Start AVAudioEngine for microphone capture (per Pattern 4 in ARCHITECTURE.md):
      - Get `inputNode` from audio engine
      - Get output format from bus 0
      - Convert to target format (44100 Hz, 1 channel, float32) using `AVAudioConverter` if needed
      - Install tap on bus 0 with bufferSize 1024
      - In tap callback: write buffer to `micAudioFile` (AVAudioFile with AAC settings: 44100 Hz, 1 channel, 128 kbps)
      - Start audio engine
   e. Start ScreenCaptureKit for system audio capture (per Pattern 3 in ARCHITECTURE.md):
      - Get `SCShareableContent` excluding current process (use `SCShareableContent.excludingDesktopWindows(true, onScreenWindowsOnly: true)` or content filter with main display)
      - Create `SCStreamConfiguration` with `capturesAudio = true`, `excludesCurrentProcessAudio = true`, sample rate 44100
      - Create `SCContentFilter` targeting the main display
      - Create `SCStream` with filter, config, and delegate
      - Add stream output for `.audio` type with `sampleHandlerQueue: audioQueue`
      - In `streamOutput(_:didOutputSampleBuffer:of:)` delegate method:
        - Convert `CMSampleBuffer` to `AVAudioPCMBuffer` (extract AudioBufferList from CMSampleBuffer, create AVAudioPCMBuffer)
        - Write to `systemAudioFile`
        - Update system audio level metering (RMS of buffer)
      - Call `stream.startCapture()`
   f. Start elapsed duration timer (updates `elapsedDuration` every 1 second)
   g. Start silence detection timer (checks every 5 seconds if both audio levels are below threshold for 30+ seconds per D-12)
   h. Set `state = .recording`

3. `stopRecording() throws -> RecordingInfo` — Full flow:
   a. Set `state = .stopping`
   b. Stop AVAudioEngine tap and engine
   c. Stop ScreenCaptureKit stream (`stream.stopCapture()`)
   d. Close both audio files
   e. Stop all timers
   f. Update `RecordingInfo` with endTime, final duration, state `.completed`
   g. Save metadata JSON file per D-11 (see Task 2 in Plan 02 for full metadata — here just save basic info)
   h. Set `state = .completed`
   i. Return the completed RecordingInfo

4. `handleDeviceChange()` — Called from notification observer:
   a. If not recording, ignore
   b. Log the device change in `currentRecording.deviceChanges`
   c. For microphone: get the new default input device, restart AVAudioEngine with new input node format. Steps:
      - Stop current engine
      - Create new AVAudioEngine
      - Get new input format
      - Install new tap with format conversion to target format
      - Continue writing to same file
   d. For system audio: ScreenCaptureKit handles device changes automatically (captures system output regardless of device) — no action needed per D-08
   e. Post system notification: "Switched to {new device name}" per D-09 using `NotificationCenter.default.post(name: .voxsliceDeviceChanged, object:)`

5. `checkSilence()` — Called by silence timer:
   a. If both mic and system audio levels are below `AppConstants.silenceThreshold`:
      - If `silenceStartTime` is nil, set it to now
      - If `silenceStartTime` + 30 seconds has passed, call `stopRecordingDueToSilence()`
   b. If either level is above threshold, reset `silenceStartTime` to nil

6. `stopRecordingDueToSilence()` — Auto-stop:
   a. Set `currentRecording.silenceDetected = true`
   b. Call `stopRecording()` (reuses normal stop logic)
   c. Post notification: "Recording stopped: no audio detected for 30 seconds" per D-12

**CMSampleBuffer to AVAudioPCMBuffer conversion:**
Extract the AudioBufferList from the CMSampleBuffer, create an AVAudioPCMBuffer from it using `AVAudioPCMBuffer(pcmFormat: targetFormat, frameCapacity: AVAudioFrameCount(sampleBuffer.numSamples))`, then copy the audio data.

**Memory management:**
- All audio callbacks write to disk immediately (AVAudioFile.write) — never accumulate buffers in memory
- Use `[weak self]` in all closure captures
- Clean up all resources in stopRecording

**Error handling:**
- If mic capture fails to start but system audio works: continue with system audio only, log warning
- If system audio fails but mic works: continue with mic only, log warning
- If both fail: throw error, set state to `.failed`

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Audio hardware -> App | Untrusted audio input from system devices; format/sample rate may change unexpectedly |
| ScreenCaptureKit -> App | CMSampleBuffer delivery may stop or arrive at unpredictable intervals |
| App -> Filesystem | Writing audio files; disk may be full, permissions may change |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | AudioCaptureService | accept | Audio input is from local hardware only; no remote attack surface |
| T-02-02 | Denial of Service | AudioCaptureService | mitigate | Handle SCStream errors and AVAudioEngine failures gracefully; auto-stop on 30s silence prevents indefinite resource consumption |
| T-02-03 | Information Disclosure | Recording files | accept | Audio files stored in user-configured local directory; user controls access. No encryption at rest for v1. |
| T-02-04 | Denial of Service | Filesystem writes | mitigate | Wrap AVAudioFile writes in try/catch; stop recording cleanly on disk-full or write errors |
</threat_model>
