### Analysis Results Display (In Menu Bar Dropdown)

Per D-12: Analysis sections shown in the menu bar dropdown as a scrollable view. This is the primary interaction surface for Phase 4.

**Layout per analysis section card:**

Each section is a horizontal rule-separated block with:
- Section title: `.headline` font weight, uppercase for visual hierarchy (e.g., "Summary", "Action Items")
- Section content: `.body` font, wrapped text, `.lineLimit(3)` with "..." truncation for long content
- Copy button: Aligned to trailing edge, SF Symbol `doc.on.doc`, `.controlSize(.small)`, `.buttonStyle(.borderless)`
- On tap of copy button: Brief visual confirmation (icon flashes to `checkmark` for 1.5s), content copied to `NSPasteboard.general`

**Section ordering (per D-05):**
1. Summary (TL;DR one-liner + detailed paragraph)
2. Action Items (numbered list)
3. Decisions (bullet list)
4. Key Topics (comma-separated tags)

**Scroll behavior:** The analysis sections are contained within a scrollable region. Maximum visible height before scrolling: ~200pt (approximately 3 sections visible).

## Interaction Patterns

### Post-Transcription Auto-Analysis Flow

Per D-09: RecordingCoordinator chains recording stop -> transcribe -> analyze. Analysis triggers automatically after transcription completes.

```
1. Transcription completes (transcriptionDidComplete notification fires)
2. RecordingCoordinator calls startAnalysis(transcript:)
3. Menu bar icon changes to sparkles (analyzing state)
4. Dropdown menu shows "Analyzing..." with progress bar
5. Progress updates:
   a. "Preparing transcript..." — formatting transcript text for AI prompt
   b. "Sending to AI provider..." — API call in progress
   c. "Processing response..." — parsing structured JSON from AI
   d. "Saving analysis..." — writing Markdown file to analysis/ directory
6a. On success:
   - Menu bar shows checkmark.circle.fill (green, brief 2 seconds)
   - Dropdown shows "Analysis complete" with summary line
   - Scrollable analysis sections appear below with copy buttons
   - Icon reverts to idle waveform.circle
6b. On failure:
   - Menu bar shows exclamationmark.triangle (orange)
   - Dropdown shows error message with "Retry Analysis" button
   - Icon stays in failed state until user retries
```

### Copy Section to Clipboard Flow

Per D-13: Per-section copy buttons in the dropdown.

```
1. User sees analysis results in menu bar dropdown
2. User clicks "Copy" button on any section (Summary, Action Items, Decisions, Key Topics)
3. System copies the section's text content to NSPasteboard.general
4. Copy button icon flashes from doc.on.doc to checkmark for 1.5 seconds
5. Text is available for pasting into any application
```

### Retry Analysis Flow

Per D-11: Same pattern as transcription retry from Phase 3.

```
1. User sees "Analysis failed" in menu bar dropdown
2. User clicks "Retry Analysis"
3. System re-attempts analysis from the beginning using the same transcript
4. Same progress flow as auto-analysis
5. If repeated failures: Error message suggests checking AI provider settings
```

### Analysis Language Configuration Flow

Per D-03: User-configurable analysis output language.

```
1. User opens Settings > General tab
2. User sees "Analysis Language" picker under "Analysis" section
3. User selects preferred language (or "Same as transcript language")
4. Selection saved to UserDefaults immediately on change
5. Next analysis uses the selected language in the AI prompt
```

## Markdown Output Format

Per D-05 through D-08: The structured Markdown file written to `analysis/` directory.

**File naming:** `YYYY-MM-DD_HH-MM-SS_analysis.md` (per D-07, consistent with recording/transcript naming)

**File structure:**

```markdown
---
date: "2026-04-07T14:30:00Z"
duration: "45m 32s"
language: "zh"
topics:
  - "Q2 Roadmap"
  - "Budget Planning"
  - "Hiring"
---

# Meeting Summary

TL;DR: {one-line summary}

{detailed paragraph summary}

# Action Items

1. {action item with owner and deadline if mentioned}
2. {action item}

# Decisions

- {decision made during the meeting}
- {decision}

# Key Topics

- **{topic}**: {brief description}
- **{topic}**: {brief description}
```

**YAML frontmatter fields (per D-06):**

| Field | Type | Source |
|-------|------|--------|
| date | ISO 8601 string | `transcribedAt` from TranscriptInfo |
| duration | Formatted string (e.g., "45m 32s") | `duration` from TranscriptInfo |
| language | Language code string | `language` from TranscriptInfo |
| topics | List of strings | Extracted from AI analysis response |

## Data Display Patterns

### AnalysisResult Data Model

The internal data model for analysis results (not directly rendered, but defines the data contract):

```
AnalysisResult {
    id: UUID
    transcriptId: UUID
    summary: AnalysisSummary {
        tldr: String           // One-line summary
        detailed: String       // Detailed paragraph
    }
    actionItems: [ActionItem] {
        index: Int
        text: String
        assignee: String?      // If mentioned
        deadline: String?      // If mentioned
    }
    decisions: [String]        // List of decision descriptions
    topics: [Topic] {
        name: String
        description: String
    }
    analyzedAt: Date
    provider: String           // "openai", "deepseek", "zhipuai"
    language: String           // Output language
    filePath: String           // Path to saved Markdown file
}
```

### AnalysisStep State Machine

```
idle -> preparing -> sending -> processing -> saving -> completed
                                              \-> failed(AnalysisError)
```

| Step | Progress Range | Menu Display |
|------|---------------|--------------|
| idle | 0.0 | (not shown) |
| preparing | 0.0 - 0.10 | "Preparing transcript..." |
| sending | 0.10 - 0.70 | "Sending to AI provider..." |
| processing | 0.70 - 0.90 | "Processing response..." |
| saving | 0.90 - 1.0 | "Saving analysis..." |
| completed | 1.0 | "Analysis complete" + results |
| failed | -- | Error message + "Retry Analysis" |

## Accessibility

- Analysis status uses `.accessibilityValue()` for screen readers (e.g., "Analyzing, 60 percent complete")
- Progress bar has `.accessibilityLabel("Analysis progress")`
- Each analysis section card uses `.accessibilityElement(children: .combine)` with label "{section title}, {content preview}"
- Copy buttons have `.accessibilityLabel("Copy {section name}")` and `.accessibilityHint("Copy this section to clipboard")`
- "Retry Analysis" button has `.accessibilityHint("Retry the failed analysis")`
- Settings language picker follows standard macOS accessibility with labels and hints
- Color is never sole indicator -- always paired with icon (sparkles for analyzing, checkmark for complete, triangle for failed) and text label
