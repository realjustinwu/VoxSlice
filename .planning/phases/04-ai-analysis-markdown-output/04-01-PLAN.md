<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| App -> AI Provider API | Transcript text sent to external AI API (OpenAI/Deepseek/ZhipuAI). API key transmitted in Authorization header. |
| AI Provider API -> App | Structured JSON response received from external service. Potentially malformed or malicious. |
| App -> Filesystem | Markdown file written to user-configured output directory. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Information Disclosure | AI API call | mitigate | API key read from Keychain (encrypted at rest), transmitted only over HTTPS. AIProvider endpoints enforce HTTPS scheme (established in Phase 1, T-01-08). |
| T-04-02 | Tampering | AI response parsing | mitigate | Validate all JSON fields before creating AnalysisResult. Safe defaults for missing fields. Guard against malformed JSON with try/catch and AnalysisError.invalidResponse. |
| T-04-03 | Denial of Service | AI API call | mitigate | 300-second timeout prevents indefinite hangs. AnalysisError.timeout for long transcripts. AnalysisError.contextTooLong for exceeding context window. |
| T-04-04 | Information Disclosure | Markdown file output | accept | Output files written to user-configured directory. Standard filesystem permissions apply. No PII beyond what user chose to record. |
| T-04-05 | Spoofing | AI API response | accept | Response comes from authenticated HTTPS endpoint. Low risk of MITM on HTTPS. No critical decisions made from analysis — user reviews output. |
| T-04-06 | Elevation of Privilege | File write path | mitigate | Use StorageService.directoryURL() which creates paths under user-configured output directory. Do not accept user-supplied filenames directly. File naming is deterministic (timestamp-based). |
</threat_model>
